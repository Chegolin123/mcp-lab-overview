# MCP-лаборатория — обзор

Четыре MCP-сервера, которые превращают рутину «десять вызовов shell» в один
типизированный инструмент.

Приватные репозитории: `obsidian-mcp`, `eljur-mcp`, `tg-mcp`, `text-mcp` —
доступ по запросу.

## Зачем это вообще

MCP-сервер оправдан, когда он **сокращает число шагов** и **убирает
неоднозначность**. Если агенту и так хватает `grep`, сервер не нужен.

## obsidian-mcp

Доступ к базе знаний по файловой системе: без запущенного Obsidian и плагинов.

| Инструмент | Что делает |
|---|---|
| `search_notes` | полнотекстовый поиск с ранжированием |
| `read_note` | чтение по имени или пути |
| `list_notes` | список с фильтрами по frontmatter |
| `get_backlinks` | обратные ссылки `[[wikilinks]]` |
| `note_index` | компактный индекс папки |

Выигрыш: один вызов вместо 10–15 `grep`/`ls`.

## eljur-mcp

Электронный дневник через официальный API: сообщения, расписание, оценки,
домашние задания, отправка сообщений. Токен кешируется, при `403` — перелогин.
Если учётные данные не заданы, сервер стартует и отдаёт понятную ошибку.

## tg-mcp

Telegram по MTProto: диалоги, сообщения, поиск по чатам, отправка. Работает
через SOCKS-туннель: у части провайдеров MTProto-серверы недоступны напрямую.
Сессия хранится локально, `api_hash` и `*.session` — секреты.

## text-mcp

Точная вставка текста на изображение по координатам: `image_info`,
`measure_text`, `add_text`, `list_fonts`. Детерминированно, на Pillow, без
браузера и API-ключей. Нужен, чтобы надпись легла в конкретное место, а не
«куда-нибудь».

## Общий вывод

Хороший MCP-инструмент — это узкий контракт с предсказуемым результатом.
Плохой — обёртка над `subprocess` с двадцатью необязательными аргументами.

## Стек

Python · FastMCP · Pillow · Telethon · httpx

## Что не публикуется

Токены, сессии, логины, структура личной базы знаний.

## Почему код закрыт

Внутри — рабочие конфиги, ключи, персональные данные и коммерческая часть.
Публиковать это нельзя, поэтому открыт только обзор: что делает система,
какие решения внутри и чему она научила.
